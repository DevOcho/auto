# auto 0.9.2

**Coming from 0.8? Read the
[0.9.0 release notes](https://devocho.github.io/auto/releases/0.9.0/) first:**
every existing cluster has to be recreated once, which resets its local
databases.

## What changed

- **`mailpit.local` works when a pod brings its own Mailpit.** A pod that
  deploys its own Service named `mailpit` replaces auto's, and auto's route
  then pointed at a port that Service didn't have, so `mailpit.local` answered
  500. The route now uses Mailpit's own web port, 8025, which both have. The
  next `auto start` fixes an existing cluster.
- **A system pod that `local.yaml` doesn't define is reported.** When a pod's
  `.auto/config.yaml` asks for a system pod with no entry in `local.yaml`,
  `auto start` now names it and the pod that asked, instead of skipping it
  without a word.
- **Images 0.9 doesn't use are skipped.** ingress-nginx and matomo images
  listed under `registry:` in `local.yaml` are skipped with a note, as
  `minio/minio` already was, instead of being pulled and cached on every
  start. You can delete those lines.
- **Caching images no longer breaks `local.yaml`.** After each start, auto
  adds newly seen images under `registry:`, always indented two spaces. In a
  `local.yaml` whose list items start flush with their key (valid YAML, and
  how YAML tools and some editors write it), that made the file unreadable,
  and every command failed until it was fixed by hand. New entries now match
  the list's indent, and auto never writes a `local.yaml` it can't read
  back.
- **`auto --version` and `auto --help` no longer ask to create the code
  folder** on a machine where it doesn't exist yet. Run from a script or CI
  with no terminal, a missing code folder now gets an error that says what to
  do, instead of a traceback.

## Upgrading

```bash
auto update
```
