# auto 0.9.4

**Coming from 0.8? Read the
[0.9.0 release notes](https://devocho.github.io/auto/releases/0.9.0/) first:**
every existing cluster has to be recreated once, which resets its local
databases.

## What changed

- **Teammates can open your sites again.** auto 0.9 made every port listen
  only on your own machine, the sites included, so a team that let others
  open a developer's sites through a hosts entry lost that. The new
  `sites-bind-address` setting shares the sites alone: with
  `sites-bind-address: 0.0.0.0` in `local.yaml`, the sites (80 and 443, or
  8088) listen on your network, while the database ports, the image registry
  and the Kubernetes API stay on your machine. Mailpit's and Floci's pages
  use the same ports, so they are shared too. Nothing changes unless you set
  it. Put it in the project's `local.yaml` to turn it on for a whole team.
  See [sharing your sites](https://devocho.github.io/auto/guides/teams/#sharing-your-sites).
- **Every release checks it.** The real `auto start` run on each Linux build
  now also turns sharing on and checks that the sites answer on the
  machine's network address while the API and the registry don't.

## Upgrading

```bash
auto update
```

To share your sites, add `sites-bind-address: 0.0.0.0` to
`~/.auto/config/local.yaml`, then recreate the cluster once. That resets its
local databases, so back them up first, as in the
[0.9.0 upgrade steps](https://devocho.github.io/auto/releases/0.9.0/#upgrading):

```bash
auto stop --delete-cluster
auto start
```

`auto start` warns when an existing cluster's sites listen somewhere other
than `sites-bind-address`.
